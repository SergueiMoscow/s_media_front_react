# FRONTEND_SPEC.md — описание текущего фронтенда s_media_front

Документ описывает поведение и сценарии приложения «Media Explorer» (фронтенд
комплекса s_media) так, чтобы по нему можно было воссоздать приложение с нуля на
React, не читая старый код. Визуальный дизайн не описывается (в новой версии будет
другим). Описывается структура экранов, навигация, состав элементов и сценарии.

---

## 1. Обзор

### Назначение

Приложение — каталогизатор фото и видео. Оно объединяет в одном месте файлы,
физически лежащие на разных компьютерах (домашний сервер, NAS и т.п.), в разных
папках и хранилищах. Система **не создаёт, не изменяет и не удаляет файлы** — только
показывает уже существующие и ведёт по ним метаданные каталога (описание, теги,
публичность, реакции-эмодзи).

Фронтенд сам не ходит к узлам: он обращается только к `s_media_api` (хостинг),
который проксирует запросы к узловому сервису `s_media_service` и проверяет JWT.

### Стек (текущий)

- Vue 3 (Composition API + SFC) на TypeScript
- Vite (dev-сервер и сборка)
- Vuetify 3 (компоненты UI), иконки `@mdi/font`
- Vue Router 4, Axios (HTTP), mitt (события), Moment (в зависимостях, но в коде не
  используется — форматирование дат написано вручную)
- Дополнительно: `@vueform/multiselect` (выбор/ввод тегов), `video.js` +
  `@videojs-player/vue` (видео), `webfontloader` (шрифт Roboto)

### Сборка

- `npm run dev` — Vite dev-сервер, слушает `0.0.0.0:3000`.
- `npm run build` — `vue-tsc --noEmit && vite build` (проверка типов + продакшен-сборка).
- `npm run preview` — предпросмотр собранного бандла.
- `npm run lint` — ESLint.

### Деплой

- Предусмотрен `Dockerfile` (образ `node:14`, `npm install`, запускает `npm run dev`).
- Реально приложение развёрнуто на хостинге через **pm2**, который запускает
  **Vite dev-сервер** (`npm run dev`) на порту 3000; перед ним стоит **nginx** с SSL
  (Let's Encrypt, редирект 80→443, проксирование на `localhost:3000`). То есть в проде
  работает dev-режим Vite, а не статический бандл.

### Адрес API

Базовый URL бэкенда задаётся переменной окружения **`VITE_BACKEND_URL`** (значение
не фиксируем). Она читается через `import.meta.env.VITE_BACKEND_URL`:

- в конфигурации axios-инстанса `apiClient` как `baseURL`;
- напрямую при построении URL изображений/файлов и при вызовах токенов в `Login.vue`
  и в перехватчике обновления токена.

## 2. Аутентификация и пользователи

### Вход

Экран `/login` — форма из двух полей («Name» / «Password») и кнопки «Login».
Формат полей: username и password.

При отправке фронт делает `POST {VITE_BACKEND_URL}/api/token/` с телом
`{ username, password }` (обычный `axios`, **без** общего перехватчика). Ответ
`{ access, refresh }`.

При успехе:
- `access` сохраняется в `localStorage` под ключом **`access_token`**;
- `refresh` — под ключом **`refresh_token`**;
- выполняется переход на `/`.

При ошибке — `alert('Ошибка входа!')`, остаётся на экране входа.

### Где хранится идентификатор

Только в `localStorage`: `access_token` и `refresh_token` (JWT). Серверных/сессионных
механизмов нет. Отдельного профиля пользователя фронт не хранит.

### Заголовки запросов

Общий axios-инстанс `apiClient` добавляет в каждый запрос заголовок
`Authorization: Bearer <access_token>` (если токен в `localStorage` есть).
Иные пользовательские заголовки фронт не шлёт (`X-USER-ID` и `X-REQUEST-ID` узел
получает от API, фронт о них не знает).

### Истечение сессии / обновление токена

Перехватчик ответов `apiClient`:

- при ответе **401** (и если запрос ещё не помечен как повторный) берёт `refresh_token`
  и делает `POST {VITE_BACKEND_URL}/api/token/refresh/` с телом `{ refresh }`;
- из ответа `{ access, refresh }` обновляет оба ключа в `localStorage`;
- повторяет исходный запрос с новым `access`-токеном;
- если обновление не удалось — удаляет оба токена и делает `router.push('/login')`.

Токен доступа на API живёт коротко (5 минут), refresh-токен — 1 день, refresh-токен
ротируется (см. API_CALLS.md).

### Выход

Кнопка «Выйти» в шапке: удаляет `access_token` и `refresh_token` из `localStorage` и
рассылает событие `auth-changed`.

### Признак «пользователь вошёл»

`isUserLoggedIn` — вычисляемое значение: `!!localStorage.getItem('access_token')`.
Пересчитывается при переключении флага-триггера, который меняется по событию
`auth-changed` (после входа/выхода/перенаправления на логин). От него зависят:

- видимость пунктов меню (защищённые пункты скрыты для гостя);
- кнопка в шапке («Войти» / «Выйти»);
- загрузка списка хранилищ для подменю «Каталоги».

Ролей как таковых нет. Доступ к данным фактически ограничивается на уровне API:
запросы вернут данные только тех серверов, которыми владеет текущий пользователь.
Гостевого просмотра публичных файлов во фронте не реализовано.

## 3. Навигация

Каркас приложения: верхняя панель (AppBar) и выдвижное меню (drawer). На всех
экранах доступны шапка и меню (единый корневой компонент).

### Верхняя панель

- кнопка-бургер слева (открывает/закрывает выдвижное меню);
- заголовок «Media Explorer»;
- справа кнопка «Войти» (если гость) или «Выйти» (если вошёл).

### Пункты меню (drawer)

| Пункт | Путь | Кто видит | Что делает |
| --- | --- | --- | --- |
| Домашняя | `/` | все | главная страница (последние файлы каталога) |
| Каталоги | `/catalog_content` | только вошедшие | подменю-группа: список хранилищ; клик по хранилищу → каталог этого хранилища |
| Хранилища | `/folder_content` | только вошедшие | содержимое хранилищ (обзор папок/файлов) |
| Серверы | `/storages` | только вошедшие | управление серверами и хранилищами |
| О системе | `/about` | все | статичное описание системы |

Пункт «Каталоги» — раскрывающаяся группа. При входе фронт грузит список хранилищ
(`GET /storages/`) и показывает их подпунктами; клик ведёт на
`/catalog_content/{server_id}/{storage_id}/` (в URL передаются `server_id` и `id`
хранилища).

Фильтрация по «только вошедшие» выполняется на клиенте (скрытие пунктов). Защиты
маршрутов (route guard) **нет** — прямой переход по защищённому URL гостем покажет
экран, а запросы упадут с 401.

### Маршруты (URL)

| Маршрут | Компонент/экран | Параметры |
| --- | --- | --- |
| `/` | Главная (Home) | — |
| `/about` | О системе (Description) | — |
| `/login` | Вход (Login) | — |
| `/storages` | Серверы и хранилища (Storage) | — |
| `/folder_content` | Хранилища (FolderContent), сводка по всем серверам | — |
| `/folder_content/:server?/:storage?/:folder_path?` | Хранилища (FolderContent) | `server` (id сервера), `storage` (UUID хранилища), `folder_path` (путь папки); `page` — query-параметр |
| `/catalog_content/:server_id?/:storage_id?/` | Каталог (CatalogContent) | `server_id`, `storage_id` |

`folder_path` в URL — путь папки внутри хранилища (относительный, без ведущего
слеша, сегменты через `/`). Переходы между папками меняют URL (с сохранением
`page` в query), поэтому работают кнопки «назад/вперёд» браузера.

## 4. Экраны

### 4.1 Главная (`/`)

**Назначение:** показать последние добавленные в каталог файлы по всем серверам.

**Состав:** заголовок «Каталогизатор систем хранения изображений.» и сетка карточек
файлов.

**Данные:** при монтировании — `GET /main/`, из ответа берётся
`response.data.results.files` (массив элементов каталога, отсортированных API по
`created_at` по убыванию).

**Карточка файла (главная):** изображение-превью (URL `preview/{server_id}/{id}`),
описание (`note`), список тегов (чипы), строка «тип — размер» и дата создания.
Карточка только для просмотра: теги и описание не редактируются (клики по тегу ни к
чему не ведут).

**Состояния:** состояний загрузки/пусто/ошибки нет — при ошибке сработает общий
`alert` (см. §10). Если файлов нет, экран просто пустой. Пагинации нет (API отдаёт
не более 10 файлов на сервер).

### 4.2 О системе (`/about`)

Статичный текст: описание приложения и комплекса (три приложения + помощник
деплоя), ссылки на репозитории GitHub, картинка-схема `s_media_schema.png`.
Текст поясняет разделы «Серверы», «Хранилища», «Каталог». Часть текста устарела
(говорит, что «Раздел Каталог в разработке»). Интерактива нет.

### 4.3 Вход (`/login`)

Описано в §2. Состояние ошибки — `alert`. Индикации загрузки нет.

### 4.4 Серверы и хранилища (`/storages`)

**Назначение:** CRUD серверов и хранилищ.

**Состав:** две карточки рядом (на мобильных — в столбик):

1. **«Серверы»** — список серверов (имя + URL) и кнопка «+» добавить сервер. У
   каждой записи кнопки «изменить» (карандаш) и «удалить» (корзина).
2. **«Хранилища»** — список хранилищ (имя, путь, `server_id`) и кнопка «+» добавить.
   У каждой записи «изменить»/«удалить».

**Данные:** при монтировании — `GET /servers/` (список серверов). Список хранилищ
пустой, пока пользователь не кликнет по серверу: клик по серверу вызывает
`GET /storages/?server_id={id}` и заполняет список хранилищ.

**Сценарии:**

- *Добавить сервер:* форма (название, URL) → `POST /servers/` → обновить список.
- *Изменить сервер:* форма с текущими значениями → `PATCH /servers/{id}/` →
  обновить список.
- *Удалить сервер:* сразу `DELETE /servers/{id}/` (без подтверждения) → обновить.
- *Добавить хранилище:* форма (выбор сервера из списка, ключ хранилища, название,
  путь) → `POST /storages/`.
- *Изменить хранилище:* форма с текущими значениями → `PATCH /storages/{id}/`.
- *Удалить хранилище:* `DELETE /storages/{server_id}/{storage_id}/`.

Формы — динамические (поля из конфигурации): текстовые поля и выпадающий список
(выбор сервера). Кнопки «Отмена» / «OK».

**Состояния:** нет загрузки/пусто/ошибки (кроме общего `alert`). Пагинации нет.

**Особенности (см. §10):** список хранилищ не обновляется автоматически после
добавления/удаления хранилища; удаление сервера/хранилища без подтверждения; поле
«ключ хранилища» присутствует в форме всегда.

### 4.5 Хранилища (`/folder_content` и `/folder_content/:server/:storage/:folder_path`)

**Назначение:** обзор файловой структуры хранилища — папки и файлы, с переходом
вглубь по папкам.

**Два режима:**

- Без параметров (`/folder_content`, пункт меню «Хранилища») — сводка по всем
  серверам пользователя: `GET /servers_content/`, показывает папки верхнего уровня
  всех хранилищ.
- С параметрами — содержимое конкретной папки хранилища:
  `GET /storage/{server}/{storage}/?folder={folder_path}&page={page}`.

**Состав:**

- шапка: «Хранилище: {storage_name}» и хлебные крошки (breadcrumbs) «Папка: <корень> /
  сегмент / сегмент …»;
- сетка карточек папок;
- сетка карточек файлов;
- пагинация внизу.

**Карточка папки:** имя, название хранилища (и имя сервера в скобках), картинка
«папка» (генерируемая, число иконок = числу вложенных папок), коллаж файлов папки,
счётчики «Папок: N (всего M)» и «Файлов: N (всего M)». Клик по карточке/картинке
переходит внутрь папки (URL + `folder_path`).

**Хлебные крошки:** «<корень>» ведёт в корень хранилища, каждый сегмент — в
соответствующую вложенную папку.

**Карточка файла:** превью (картинка) или видеоплеер, редактируемое описание,
имя файла, мультиселект тегов, чекбокс «public», строка «тип — размер» и дата.

**Пагинация:** постраничная, номер страницы синхронизирован с `?page=`. Размер
страницы на фронте зафиксирован 20 (`limit=20`). Всего элементов — `pagination.items`
из ответа. Смена страницы обновляет URL и перезагружает данные.

**Состояния:** ошибка только логируется в консоль; загрузка/пусто не оформлены.
При переключении страницы/папки данные подменяются, список папок строится
асинхронно (коллажи грузятся параллельно).

### 4.6 Каталог (`/catalog_content/:server_id?/:storage_id?`)

**Назначение:** просмотр и фильтрация файлов, занесённых в каталог выбранного
хранилища, с редактированием метаданных.

**Состав:**

- панель фильтра;
- сетка карточек файлов (та же карточка, что в «Хранилищах»: превью/видео,
  описание, теги, «public», размер/дата).

**Данные:** при монтировании (и при изменении фильтра) —
`GET /catalog_content/{server_id}/{storage_id}/` с параметрами фильтра. Ответ:
`response.data.files` (список файлов) и `response.data.pagination.page`.

**Панель фильтра:**

- текстовое поле поиска (кнопка-лупа применяет поиск);
- мультиселект тегов (можно выбирать и создавать новые теги);
- меню «Фильтр» (кнопка-шестерёнка):
  - «Фильтр по публикации» (выпадающий список: Все / Опубликованные /
    Неопубликованные);
  - «Фильтр по дате» (переключатель) + при включении поля «Дата от» / «Дата до»;
  - «Сортировка» (выпадающие списки поля и направления);
  - кнопки «Отмена» / «Поиск».

**Клик по тегу в карточке файла** добавляет/убирает этот тег в фильтре и
перезапрашивает список (пересечение/накопление тегов).

**Состояния:** загрузки/пусто/ошибки нет. Пагинации в UI нет (параметры `page`/
`per_page` отправляются, но переключателя страниц на экране нет — фактически
показывается только первая страница).

**Важно (см. §10):** выпадающие списки «Фильтр по публикации» и «Сортировка»
визуально присутствуют, но не подключены к параметрам запроса (не влияют на
результат). Реально работают поиск, теги и фильтр по дате.

## 5. Работа с медиа

### Источники URL

Все URL медиа строятся на клиенте из `VITE_BACKEND_URL` и идентификаторов:

**Превью изображения:**

- файл из хранилища (есть `name`): `{BASE}/preview/{server}/{storage}/?folder={folder_path}&filename={name}`;
- файл из каталога (есть `id`): `{BASE}/preview/{server}/{id}/`.

**Файл целиком (для видео):**

- файл из хранилища: `{BASE}/file/{server}/{storage}/?folder={folder_path}&filename={name}`;
- файл из каталога: `{BASE}/file/{server}/{id}/`.

**Картинка-заглушка папки:** `{BASE}/folders_image?folders={N}&timestamp=…&rand=…`,
где `N` = `folders_count.direct` (число иконок-папок на коллаже). `timestamp`/`rand`
— клиентский анти-кэш.

**Коллаж файлов папки:** `{BASE}/folder_collage/{server}/{storage}/?folder={folder}&timestamp=…&rand=…`.
Ответ — бинарные данные изображения (`responseType: 'arraybuffer'`), фронт
преобразует в `data:image/jpeg;base64,…` и вставляет как `src`.

### Показ превью

Карточка файла определяет тип по расширению (регистронезависимо):

- **изображения:** `png, jpg, jpeg, bmp, svg, webp` → `<img src=preview>`;
- **видео:** `mp4, webm, ogv` → видеоплеер (video.js): poster = превью, src = file URL,
  `controls`, `loop`, громкость 0.6, ширина 200.

Для изображений превью — это уменьшенная версия (ширина задаётся на сервисе).
Открытия полноразмерного изображения/лайтбокса нет: клик по картинке не делает
ничего (обработчик пустой).

### Навигация между файлами

Сквозного просмотра (слайдер/лайтбокс с переходом «след./пред.») нет. Навигация —
только между папками через карточки папок и хлебные крошки (обновляется URL), и
между страницами через пагинацию.

## 6. Редактирование каталога

Редактирование доступно на карточке файла (в экранах «Хранилища» и «Каталог»).
При любом изменении (описание, тег, публичность) файл получает/обновляет запись в
каталоге на узле.

### Описание (note)

Поле-инпут с кнопками «сохранить» (зелёная галочка) и «отмена» (крестик) —
появляются при фокусе. Сохранение отправляет `POST /storage/fileinfo/{server}/{storage}/`
с телом:

- для файла из хранилища: `{ folder_path, filename, note }`;
- для файла из каталога: `{ id, note }`.

### Теги

Мультиселект (можно выбирать из существующих и вводить новые, `createTag`).
Изменение отправляет тот же `POST …/fileinfo/` с телом `{ id, tags }` или
`{ folder_path, filename, tags }`. Пустой список тегов — допустимое значение (теги
просто снимаются).

### Публичность

Чекбокс «public»: изменение отправляет `POST …/fileinfo/` с `{ id, is_public }` или
`{ folder_path, filename, is_public }` (boolean).

### Эмодзи (реакции)

В модели данных поле `emoji` есть, но **в UI редактора нет** — изменить реакции
через фронт нельзя.

### Правила и ограничения

- Редактировать может только авторизованный пользователь; реально данные привязаны
  к владельцу на уровне API/сервиса (фронт проверок не делает).
- Файл «из хранилища» идентифицируется тройкой `folder_path` + `filename`; файл «из
  каталога» — `id`. Тело запроса строится в зависимости от того, какое из полей
  (`name` или `id`) присутствует.
- Клиентские валидации отсутствуют; ошибки приходят из API и выводятся через `alert`.

## 9. Правила и поведение в клиенте

### Валидация

Клиентских валидаций почти нет:

- форма входа — только HTML-атрибут `required` на полях;
- формы серверов/хранилищ — поле помечено `required`, но фактической проверки нет;
- прочие поля (теги, описание, публичность, даты) — без валидации.

### Форматирование

- **Дата/время** (`formatDate`): из ISO-строки в локальное время как
  `ДД.ММ.ГГГГ ЧЧ:ММ` (с ведущими нулями). Используется локальный часовой пояс
  браузера.
- **Размер файла**: `(size / 1024).toFixed(2) + ' KB'` (всегда в КБ, без приведения к
  МБ/ГБ).

### Подготовка параметров каталога (prepareRequestParams)

- `tags` (массив) → строка через запятую.
- если `date_filter = false` — параметры `date_from` и `date_to` не отправляются;
- если `date_filter = true` — `date_from`/`date_to` проверяются regex
  `\d{4}-\d{2}-\d{2}`; невалидная `date_from` → `1900-01-01`, невалидная `date_to` →
  сегодняшняя дата;
- `public === null` — параметр не отправляется;
- пустые `sort` / `sort_direction` — не отправляются.

### Сортировка

Сортировка на фронте не выполняется — порядок задаёт API/сервис (по умолчанию
`created_at desc`). Поля сортировки в UI: «Дата» (`created_at`) и «Описание»
(`note`); направление «По возрастанию»/«По убыванию». (См. §10: фактически не
подключено.)

### Значения по умолчанию

- Фильтр каталога: `page=1`, `per_page=10`, `date_filter=false`, `date_to` = сегодня,
  `public=null`, `sort=''`, `sort_direction=''` (см. DATA_MODELS.md).
- Пагинация в «Хранилищах»: `limit=20`.
- Начальная страница при отсутствии `?page` — 1.

### Локализация (языки)

Единого механизма i18n нет. Строки интерфейса частично на русском («Домашняя»,
«Каталоги», «Хранилища», «Серверы», «О системе», «Выйти», «Фильтр», «Поиск»,
«Дата от/до», «Сортировка», «Отмена»), частично на английском («Media Explorer»,
«Sign in», «Name», «Password», «Login», «Search», «public», «Select your
characters»). Даты/размеры локализованы только форматом, без учёта локали браузера.

## 10. Особенности и проблемы

Места, которые выглядят как ошибки, костыли или случайное поведение. Помечены
«не повторять» либо «спросить у владельца».

1. **Нет route guard'ов.** Защита страниц только скрытием пунктов меню. Гость, открыв
   `/storages` или `/folder_content` напрямую, увидит «битую» страницу (401 →
   попытка refresh → redirect на `/login`). *Спросить у владельца, нужна ли защита
   маршрутов.*

2. **Фильтр «по публикации» и «сортировка» не подключены.** В `FilterComponent`
   выпадающие списки связаны с локальными переменными, которые не попадают в
   параметры запроса. Работают только поиск, теги и фильтр по дате. *Не повторять;
   либо реализовать по-настоящему.*

3. **Параметр `date_filter` уходит на бэкенд** (он не вырезается в
   `prepareRequestParams`), хотя на сервисе такого параметра нет (игнорируется). *Не
   повторять: это чисто клиентский флаг, не должен уходить в запрос.*

4. **`/servers_content/` — расхождение формы ответа.** Фронт ожидает
   `results.storage_name`, `results.path`, `results.files`, а эндпоинт возвращает
   `results.folders`. В результате шапка («Хранилище: …») в этом режиме пустая, файлы
   не показываются — только папки. *Сверить контракт (см. API_CALLS.md).*

5. **Каталог без пагинации.** `catalog_content` отправляет `page`/`per_page`, но на
   экране нет переключателя страниц — видна только первая страница (10 файлов). *Не
   повторять; решить: пагинация или бесконечная прокрутка.*

6. **Список хранилищ не обновляется** после добавления/удаления хранилища в экране
   «Серверы» (после `addStorage`/`deleteStorage` нет перезагрузки списка хранилищ;
   вызывается `fetchServers`, а не `fetchStorages`). *Не повторять.*

7. **Удаление без подтверждения.** Удаление сервера и хранилища выполняется сразу по
   клику на корзину. *Спросить у владельца, нужно ли подтверждение.*

8. **Дубли ключей в списках.** На главной карточки рендерятся с `key=file.note` — при
   совпадающих описаниях возникают дубли ключей. В каталоге/хранилищах ключ из
   `name+id`. *Не повторять.*

9. **Декоративный чекбокс.** В карточке файла есть верхний чекбокс выделения без
   `v-model`/обработчика (поле `selected` в модели не используется). *Не повторять
   либо реализовать групповые операции.*

10. **`alert()` как обработка ошибок.** Все ошибки API выводятся через `alert` с
    текстом, собранным из полей тела ошибки (см. API_CALLS.md). Состояний
    загрузки/пусто/ошибки на экранах нет. *Не повторять — сделать нормальные
    состояния и тосты.*

11. **В проде работает dev-сервер Vite** (через pm2), а не статический бандл.
    *Спросить у владельца, каким должен быть деплой в новой версии.*

12. **Мёртвый код:** `src/navigationMenu.ts`, `src/components/Tags.vue`,
    `src/layouts/default/*` не используются. *Не переносить.*

13. **Клик по изображению/тегу не делает ничего** (пустые обработчики `fetchImage`,
    `handleTagClick` в `FileViewComponent`). *Спросить у владельца, задумывался ли
    лайтбокс/переход по тегу.*

14. **`Moment` в зависимостях, но не используется** (форматирование дат — ручное).
    *Не повторять.*

15. **Поле «ключ хранилища»** в форме хранилища есть всегда (даже при редактировании),
    но при показе форм его значение не сбрасывается/не заполняется явно. Ключ — это
    ключ доступа к узлу для операций записи. *Уточнить, нужен ли он в форме
    редактирования.*
